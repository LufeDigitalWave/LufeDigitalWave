## 🚀 Projetos em destaque

### 🧠 Recommendation Engine determinístico (substituindo RAG)
> Pipeline de recomendação personalizada em 5 etapas — sem chamada de LLM no caminho crítico.

**Problema:** sistema RAG anterior tinha latência alta, custo por inferência crescente e dificuldade de auditar *por que* uma recomendação aparecia.

**Solução:** N8N orquestrando 3 workflows + Supabase com `pg_trgm` para fuzzy match + tabela de sinônimos canônicos + protocolo de relaxamento em 5 níveis quando a intersecção fica vazia. Determinístico, auditável, sub-segundo.

**Stack:** `N8N` · `Supabase / PostgreSQL` · `pg_trgm` · `Vertex AI Embeddings` (offline) · `Node.js`

**Impacto:** redução drástica de custo de inferência, latência < 1s, decisões 100% explicáveis, cobertura de 90+ profissionais e 56 programas catalogados com metadados.

`🔗` [deterministic-recommendation-engine](https://github.com/LufeDigitalWave/deterministic-recommendation-engine)

---

### 🧬 Self-Hosted Conversational RAG Stack
> Stack open-source 100% on-premise — embeddings (BGE-M3) e reranking (bge-reranker-base) sem chamada externa.

**Problema:** RAG SaaS escala caro, adiciona latência e exige confiar conteúdo sensível a terceiros — inviável pra verticais com soberania de dados (saúde, jurídico, gov).

**Solução:** Hugging Face TEI rodando localmente (BGE-M3 + reranker) + pgvector pg16 + n8n em modo queue + Chatwoot + painel admin Next.js híbrido (RAG decide *o que* buscar localmente; Claude API só compõe a resposta final). Tudo orquestrado em Docker Swarm com Traefik + Let's Encrypt automático.

**Stack:** `Docker Swarm` · `Traefik v3` · `HF TEI` · `BGE-M3` · `pgvector pg16` · `n8n (queue)` · `Chatwoot` · `Next.js` · `Claude API`

**Impacto:** ~1.300 execuções/dia, latência RAG (embed → rerank → top-5) < 600ms, custo de embeddings = $0, uptime > 99.8% em 5+ meses.

`🔗` [self-hosted-rag-stack](https://github.com/LufeDigitalWave/self-hosted-rag-stack)

---

### 💬 SDR Agent template (WhatsApp Cloud API + RAG)
> Template multi-cliente de agente SDR para qualificação de leads em WhatsApp oficial, com handoff humano.

**Problema:** times comerciais B2B/B2C perdiam leads no primeiro contato — resposta lenta, qualificação inconsistente, sem rastreamento.

**Solução:** agente conversacional em WhatsApp Cloud API com classificação de momento de compra, RAG sobre base institucional (pgvector), cadência de reativação (D0/D3/D7/D14), pausa automática quando humano assume e logs estruturados pra Chatwoot/CRM.

**Stack:** `Python` · `FastAPI` · `OpenAI gpt-4.1-mini` · `Supabase/pgvector` · `WhatsApp Cloud API` · `Chatwoot` · `Docker Swarm`

**Impacto:** 150+ leads reativados em batch único, qualificação automática 24/7, 290+ testes unitários e E2E, deploy em produção em 3 clientes ativos.

`🔗` [whatsapp-sdr-agent-template](https://github.com/LufeDigitalWave/whatsapp-sdr-agent-template)

### 📱 Open-Source WhatsApp Orchestration Stack
> Stack 100% open-source pra WhatsApp **sem depender de WABA Meta** — integrando com qualquer backend de negócio existente.

**Problema:** aprovação WABA tem burocracia, custo e tempo de setup que inviabilizam casos de uso onde o WhatsApp é só um canal complementar de uma plataforma vertical já existente.

**Solução:** Evolution API (Baileys multidispositivo) → Chatwoot inbox API → n8n decide e chama o backend operacional do cliente via REST (Basic Auth / Bearer / OAuth). NocoDB pra time não-técnico operar tabelas. Patterns de integração documentados pros 5 casos mais comuns.

**Stack:** `Evolution API` · `Chatwoot v4` · `n8n` · `NocoDB` · `PostgreSQL` · `Redis` · `Docker / EasyPanel`

**Impacto:** provisionamento da stack em < 30min (incluindo TLS), ~5-10k mensagens/dia por número, integração com backend de negócio em < 400ms. Inclui matriz honesta de quando NÃO usar (disparo massivo, e-commerce, compliance).

`🔗` [open-source-whatsapp-stack](https://github.com/LufeDigitalWave/open-source-whatsapp-stack)

### 🎬 Pipeline de extração de metadados de vídeo
> Transcrição + extração estruturada em batch via Gemini File API.

**Problema:** catálogo de 400+ vídeos sem metadados padronizados pra alimentar busca semântica e recomendação — extração manual seria inviável.

**Solução:** pipeline Python que sobe vídeo pra Gemini File API, gera transcrição com timestamps, extrai 12 campos estruturados (intensidade, equipamento, foco muscular, nível, duração efetiva, etc.) com schema validation, e popula tabela Supabase com retry, dedup e checkpoint.

**Stack:** `Python` · `Gemini Pro 1.5 / File API` · `Pydantic` · `Supabase` · `asyncio` · `tenacity`

**Impacto:** 400+ vídeos processados em batch, 12 campos por vídeo, base preparada pra busca semântica e fallback de recomendação.

`🔗` [video-metadata-pipeline-template](https://github.com/LufeDigitalWave/video-metadata-pipeline-template)

### 🏛️ Chatbot GovTech — atendimento ao cidadão
> Plataforma de atendimento via WhatsApp com painel administrativo Jira-like.

**Problema:** prefeituras de médio porte queriam canal de atendimento moderno (WhatsApp) com rastreabilidade, SLA e integração ao fluxo interno (Jira-like), mas sem reescrever sistemas legados.

**Solução:** stack FastAPI + Supabase + WhatsApp Cloud API + painel React multi-tenant. Cidadão abre demanda no WhatsApp, agente IA qualifica e abre issue, equipe responde no Jira — bot espelha a resposta de volta. Inclui dual-write Jira, NPS, SLA, respostas prontas, exportação .ics, portal público de protocolo e conformidade LGPD (auditoria, 2FA, rotação de refresh token, CSP).

**Stack:** `FastAPI` · `React` · `Supabase` · `WhatsApp Cloud API` · `Jira REST` · `Docker Swarm` · `Traefik` · `GitHub Actions`

**Impacto:** 290+ testes BE / 153 FE, deploy em produção, portal público live, 100% de paridade no dual-write, 8 features GovTech (NPS/SLA/cycle-time/email-to-issue/etc).

`🔗` [govtech-citizen-chatbot-template](https://github.com/LufeDigitalWave/govtech-citizen-chatbot-template)
